# Magazine Staff Mode — Build Plan

Turning the current issue/page editor into a full virtual editorial + marketing department. This is genuinely large, so it ships in phases. **Phase 1** is what I'll build immediately; Phases 2–4 each end in a working app you can use.

---

## The cast (10 AI staff roles)

**Editorial**
- Editor-in-Chief — sets direction, approves issues, flags weak pages
- Managing Editor — owns deadlines, status, who's blocked on what
- Copy Editor — line edits, grammar, house style
- Fact-Checker — flags claims, requests sources, verifies citations
- Photo Editor — picks/critiques images, requests new ones, writes captions
- Art Director — layout critique, typography, cover concepts

**Marketing & Growth**
- SEO Lead — titles, meta, keyword plan, internal linking per article
- Social Media Manager — IG/X/LinkedIn/TikTok posts tied to each article
- Newsletter Editor — subject lines + email drafts per issue
- Ad Strategist — search/social/display ad variants + audience notes

Each role is a system-prompted Lovable AI agent with read access to the current issue, pages, and attachments, plus tools to leave structured notes (comments, status changes, marketing artifacts).

---

## Surfaces

1. **Staff drawer** (always available) — list of the 10 roles. Click one → opens that staff member's chat thread, scoped to the current issue.
2. **Shared Inbox** — chronological feed of every handoff, comment, suggested edit, and produced artifact across all staff, with filters by role / page / status (unread, action needed, resolved).
3. **Production Board**
   - **Kanban**: columns `Idea → Drafting → Copy edit → Fact-check → Art → Approved → Published`. Cards = pages.
   - **Calendar**: month/week view of issue publish dates + scheduled social/newsletter sends.
   - **Per-issue checklist**: compact panel on the issue page — what's done, what's pending, who owns each item.
4. **Marketing artifacts panel** — for each page/article: tabs for *Social*, *Newsletter*, *Ads*, *SEO brief*. Generated by the relevant role, stored, regeneratable, copyable.

---

## Phase 1 — Staff + per-staff chat (ship first)

Goal: real, working AI staff you can talk to per issue.

- New tables: `staff_threads` (one per staff member per issue) and `staff_messages` (UIMessage[]). RLS scoped to `auth.uid()`.
- Server fn `chatWithStaff({ role, issueId, messages })` using AI SDK + Lovable AI Gateway. Each role gets its own system prompt and is given issue/page context.
- UI: **Staff drawer** in the issue editor with the 10 role cards (avatar + tagline + unread dot). Click → opens that role's chat panel using AI Elements (`Conversation`, `Message`, `MessageResponse`, `PromptInput`).
- Threads keyed by `(issueId, role)`; messages persist; reload restores the right history.

## Phase 2 — Shared Inbox + structured suggestions

- Add `staff_notes` table: typed notes (`comment | edit_suggestion | status_change | flag`) with `page_id`, `role`, `status` (open / resolved), `payload` JSON.
- Give each staff role a tool (AI SDK `tool({ inputSchema, execute })`) to create notes. The chat persists narrative; the inbox surfaces actionable items.
- **Inbox** route at `/_authenticated/inbox` with filters (role, page, status) and one-click resolve / reply (jumps back into that role's chat thread).

## Phase 3 — Production board

- Add `page_status` column + `page_assignments` (role → page).
- **Kanban** at `/_authenticated/board` (drag between status columns; cards link back to the page).
- **Calendar** at `/_authenticated/calendar` (publish dates + scheduled marketing sends).
- **Per-issue checklist** rendered inline on the issue page, auto-built from page statuses + open notes.
- Managing Editor agent gains tools to move statuses and assign roles.

## Phase 4 — Marketing artifacts

- `marketing_artifacts` table keyed by `page_id` + `kind` (`social_ig | social_x | social_li | social_tt | newsletter | ad_search | ad_social | ad_display | seo_brief`).
- Each marketing role's chat exposes a "Generate" action that calls a server fn returning structured output (AI SDK `Output.object`) for that artifact kind.
- **Marketing tab** on each page: per-platform previews, copy-to-clipboard, regenerate with feedback, version history.

## Technical notes

- Stack: TanStack Start server fns (`createServerFn` + `requireSupabaseAuth`), AI SDK with Lovable AI Gateway (default model `google/gemini-2.5-flash`, escalate to `gemini-2.5-pro` for EIC / Art Director). No edge functions.
- UI: AI Elements (`Conversation`, `Message`, `MessageResponse`, `Tool`, `PromptInput`, `Shimmer`) — install in Phase 1.
- All new tables RLS-scoped to `auth.uid()` like existing `issue_attachments` / `issue_chats`.
- Storage: Lovable Cloud (existing Supabase).
- Each role gets a generated avatar (one-time `imagegen`) so the staff drawer feels like a real masthead, not lucide icons.
